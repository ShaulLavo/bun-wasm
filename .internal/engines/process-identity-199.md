## Contract and caller types

Use E for an execution/member handle and P/Q for immutable logical process/creation-parent IDs. Keep `runtime_proc.getpid()` returning E. Import exactly `runtime_proc.process_id() -> i32` and `parent_process_id() -> i32`. One common data-native `processIdentity(): [pid: number, parentPid: number]` calls those imports, validates positive P and nonnegative Q different from P, and supplies the existing public properties. Missing admission is an error, never E, constants, environment or physical host IDs.

Waffle owns the separate `processIdentity` context/client field, required `ProcessABIOptions.processIdentity`, `processKind: "process" | "thread"`, authenticated admitted-child P/Q/kind, exec membership and rewriter signatures. Missing or mismatched admitted pairs/kinds are `EINVAL`, with owned rollback. Ordinary children have P = returned E and Q = caller P; thread and nested-thread members copy caller P/Q. Parent or leader exit leaves Q unchanged. Threads never exec; a leader's exec remains blocked by published, selected or collected siblings until no-consumer rollback or full authoritative cleanup including native return. Bun adds no alternative membership service.

## Native admission choice

Retain native root E0. Before any child can reserve, explicitly consume P1 from the existing authoritative `Supervisor.next` allocator under its lock and publish root identity 1/0. Thus the first child or member gets E2; an ordinary child reports 2/1, a thread reports 1/0. This is an allocation, not `getpid + 1`. Keep current E0 sentinel behavior instead of changing unrelated ownership policy.

Private Rust `ExecutionId`, `LogicalPid` and `ProcessIdentity` distinguish the two ID meanings. Typed process/thread membership carries the pair and kind together; non-cloneable `AdmittedProcess` owns that membership, runtime and cancellation binding. A defaulted typed enum field accepts omission as Process and rejects explicit null or malformed kinds. `Runtime::admit_root(cancel)` reserves once and inserts the authoritative root record under the supervisor lock. Child admission checks the live actual caller and chooses the pair before the native child thread starts. Thread creation failure may burn an ID but must roll back unpublished admission/resources.

Store P/Q/kind in `Child` and carry `AdmittedProcess` separately from stdio into `run_instance`, `run_module_instance` and `Processes::new`, for ordinary and linked programs. Remove the ability of `Stdio.pid` alone to fabricate identity; use admission E for linked member selection. Existing optional `linked::Admission` is memory admission and remains separate. `Processes::new` neither allocates nor silently admits roots. Scalar getters read the stored pair under existing cancellation guards, with no leader lookup.

Migrate every native constructor and test fixture: `main.rs`, `process/tests.rs`, `slots/tests.rs`, `startup_tests.rs`, `nested_tests.rs`, `shm/tests.rs`, and `shm/group_pin_tests.rs`. Replace synthetic stdio-PID identity tests with real root/child/member admissions. Add allocator-order, duplicate-root, malformed-kind, cancelled-caller, creation-failure rollback, immutable ancestry and scalar-after-creator-exit tests. Native exec stays unsupported, so no new native exec membership mechanism is needed.

## Identity-sensitive callers and limits

- `process.kill(process.pid)` compares P locally and calls `hostSignal(signal, 3)`, which is bound to the current execution. It never forwards P into `procKill`. Root E0/P1 therefore has no numeric lookup mismatch. In a thread it still signals only that member, not the process leader or whole logical process. Keep that policy and test it explicitly with a handled signal. The zero-signal self probe remains local.
- `package_scripts.ts` also uses that local self-signal path; no new P-to-E translation belongs there. `source_prepare.ts` combines public P with the existing distinct `threadId` for realm naming. `util.ts` uses P only for formatted output.
- `spawn.ts` waits, kills and polls `Child.pid`, which remains E. Ordinary child P equals E; internal worker handles remain their distinct E. A thread can wait only for its own execution-owned children. A child's public Q names the creating process P, not the thread E; this grants no permission to signal or wait for its parent or a sibling's child.
- Native `Processes::kill`, `wait`, job ownership, retained `parents`, shared-memory routes and `runtime_proc.getpid` stay in E. No logical-group target remapping, signal permission change, descriptor sharing or new lifetime policy is included. Bun still ends its owned workers on main-guest exit; native runtime shutdown still cancels/joins descendants.
