# Build the experimental SpiderMonkey library

This builds a pinned Mozilla SpiderMonkey static library for `wasm32-wasip1`.
It does not add SpiderMonkey to Bun or prove that either interpreter tier runs
correctly. See the [build provenance record](bun-patches/spidermonkey-wasi.md).

The build uses the existing wasi-sdk and consumer sysroot without changing them.
It needs Python 3.10 through 3.14, Rust 1.95 or newer, Node.js 24 or newer,
`llvm-readobj`, and cbindgen 0.29.4. Install cbindgen in the configured Cargo cache:

```sh
source env.sh
cargo install --locked --version 0.29.4 cbindgen
```

Choose a private build directory and run the build through your machine's build
scheduler. The default parallelism is six jobs.

```sh
source env.sh
export SPIDERMONKEY_BUILD_DIR=$(mktemp -d /work/tmp/bun-wasm-spidermonkey-XXXXXX)
spidermonkey/build.sh
```

The outputs inside that directory are:

- `libspidermonkey_bunwasm.a`, the PIC library without `libjsrust.a` or libc.
- `obj/dist/include/` and `obj/js/src/js-confdefs.h`, the build's public headers
  and the required consumer configuration header.
- `compile_commands.json`, the compiler database generated by Mozilla's clangd
  backend.
- `receipt/vm-library.json`, archive identity, flags, target, header identity,
  relocation counts, and exception-tag checks.
- `receipt/headers.json` and `receipt/archive-objects.txt`, the checked inputs.

Repeated builds reuse the object directory and replace the packed archive.
The caller owns teardown. Keep the receipts you need, then remove the private
build directory after its processes stop. Do not retain the checkout or archive
as an accepted engine generation. Engine integration still requires both tiers'
interrupt smoke tests and producer admission.
