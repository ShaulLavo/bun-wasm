## Bun generated builtins

Class **Port**. Upstream Bun source revision `a7733435cf40429e3b35c36072769df2052b80f1`, generated by `src/codegen/bundle-modules.ts`. The source modules are `src/js/internal/freelist.ts`, `src/js/internal/fixed_queue.ts`, `src/js/internal/streams/duplexpair.ts`, `src/js/internal/streams/fast-utf8-stream.ts` (see [bun-fast-utf8-stream.md](bun-fast-utf8-stream.md)), `src/js/node/querystring.ts`, `src/js/node/punycode.ts`, and `src/js/node/wasi.ts`, plus the [thirdparty fetch modules](bun-thirdparty-fetch-builtins.md). `duplexpair.ts` requires `internal/streams/duplex`; that dependency is not embedded, and the loader resolves it to bun-wasm's own `node:stream` Duplex (see [builtin-loader-adapter.md](builtin-loader-adapter.md)). The module-name table comes from the generated internal-module registry and `src/jsc/modules/NativeModuleList.h`. Native-hook identities come from `GeneratedJS2Native.h`. Error-code ordering comes from `src/jsc/bindings/ErrorCode.ts`.

The numbered JavaScript files in `crates/bunwasm-runtime/generated/builtins/` retain Bun's generated implementations. The local generator changes intrinsic identifiers, intrinsic property calls, private property names, and the module export marker. It preserves the module's algorithms. The registry, binding names, and catalog are derived upstream data, rather than handwritten runtime implementations. `scripts/generate-bun-builtins.sh --check` reproduces every generated file. Bun's license is retained alongside the generated sources. The generator reads registry format 2 (Bun 1.4.5 added an engine stamp to the header; the module index is unchanged) and passes Bun's own WebKit version to `bundle-modules.ts`, which requires it for that stamp. The lowered output does not carry the stamp. Module ids follow Bun's registry order, so the numbered file names change whenever Bun adds a module.
