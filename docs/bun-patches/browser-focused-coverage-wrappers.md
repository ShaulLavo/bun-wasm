# Focused browser coverage wrappers

Classification: original adapter. No upstream source is copied or patched.
The local harnesses and wrappers target repository foundation
`25cb86e72528a783356ea479a0029da042a019a6`.

The three feature wrappers under `scripts/` connect the existing interruption,
worker-module and terminal-stdin drivers to the shared coverage boundary and
supervised child ledger. Explicit owner/engine selections determine rows and
artifacts. Chromium interruption includes Firefox once; WebKit runs once.
Consumers use the verified site and private interruption staging without builds.

`web/tests/browser-worker-modules.ts` retains twenty controlled invocations on
one page, a separately opened uncontrolled context and both original HTTP
observations. Durable records keep variant, iteration and outcome. A failed
context must close before another variant starts; an unproved close stops reuse.

`web/tests/playground-stdin.ts` keeps its named `checkPlaygroundStdin` export and
all six command forms on one terminal. Every case retains its original exit,
TTY, data and EOF assertions. Foreground termination and an idle observation
precede any continuation. The focused driver accepts exactly one browser and
preserves Chromium desktop and WebKit iPhone 15 contexts. Its 840-second outer
hang cap fits below the ordinary 900-second child supervisor while allowing all
six cases and recovery; individual command waits stay unchanged.

Each Bun wrapper has a 3,120-second hang cap. Interruption uses the separate
1,400-second child supervisor. Selected rows and controls remain required after
failure or cancellation; unsafe cleanup stops reuse. Real producer/browser
qualification remains an integration gate, separate from source-only controls.
