`mock.module(specifier, factory)` resolves the specifier from the calling file (the first non-runtime stack frame) the way an import would, ignoring earlier mocks, so a package is mocked at its `import` entry as in Bun. The resolver maps that target to a plugin module key: a file by its path, a missing relative or absolute file by its path normalized against the caller's directory, a builtin by its canonical `node:` name, and any other missing name by the name itself. Every later import or `require()` that resolves to the target, through any spelling, loads the key, whose exports are the factory's result; mocking the same target again replaces the earlier mock. A builtin mock covers imports only: `require("node:os")` keeps the real module, as native Bun 1.4.4 does. `require.resolve`, `import.meta.resolve(Sync)` and `Bun.resolveSync` report the target, not the key. `Bun.plugin.clearAll()` removes every mock.

The factory runs once, on first use, and a non-object result is Bun's `mock(module, fn) requires a function that returns an object`. The mock's exports are the factory's result, and its `default` key is the default export, as for an ES module (`bootstrap.js` `builtinImport`, used by the QuickJS and JSC loader and by `web/src/engine-host.js`); other builtins keep the CommonJS default of the whole exports object. As in Bun, an async factory's result is what the module becomes once it settles. Before any module graph links (a test file, a preload, the entry and every dynamic import), `bun_test.js` settles every pending async-function factory, plus the imported mock if its result is any other thenable, so static imports of the mock link against the settled value; a rejected factory fails the import that links it with the original error. `require()` reads the promise's state without waiting: pending is Bun's `require() async module "<path>" is unsupported. use "await import()" instead.` TypeError, fulfilled is its value, rejected throws the reason. The runtime watches the factory's promise and also asks the engine's promise-state peek; the browser engine has no peek, so there a promise that is already fulfilled when the factory returns (an async factory that never awaits) still reads as pending until a microtask later. A sync factory's thenable result that is not a Promise is a plain value for `require()`; a Promise follows the pending, fulfilled and rejected rules above. A replaced or cleared mock's factory never runs. A missing file is also found through its absolute `file:` URL. Each factory runs inside a private `AsyncLocalStorage` store naming its mock and the mocks whose factories led to it, which follows its awaits, and each mock records which mocks its chain is waiting on. An import never waits on a mock that is in its own chain or is waiting, directly or through other mocks, on one that is, so a factory's own imports and two factories that import each other's targets cannot deadlock. Such an import of a pending mock gets an empty module, as in Bun's cycles, and a factory that loads its own target synchronously gets an empty object instead of recursing. Imports from outside the cycle, concurrent ones included, wait for it. Native Bun then also returns that empty module to the outer import, which bun-wasm does not copy.

Native Bun also rewrites the exports of a module that was already imported. bun-wasm cannot patch an evaluated ES module namespace on every engine, so a module imported before `mock.module` keeps its original exports; call `mock.module` first, or import the module dynamically afterwards, as Bun's documentation shows.

Other known differences from native Bun:

- An async factory runs at the next module link (the next test file, preload or dynamic import) even if its module is never imported; native Bun runs it only when the module is imported.
- A sync factory that returns a Promise, such as `() => import("./fake.ts")`, breaks static imports of the mocked module with the `require() async module` error; native Bun awaits it. Settling every mock whose result is a thenable before linking would fix this.
- A mock's module namespace always has a `default` export (undefined when the factory's result has no `default` key), so `Object.keys(namespace)` lists it and a default import of such a mock gives `undefined`; native Bun leaves it out and a default import is a `SyntaxError`.
- A rejected factory that nothing awaits does not fail the test as an unhandled rejection, as it does in native Bun, because the runtime watches the factory's promise.

`cargo test -p bunwasm-runtime resolve` covers re-mocking, missing files, builtins and package entries in the resolver. `tests/fixtures/bun-probe-test` (`probe.test.ts` and `module-mocks.test.ts`) compares re-mocking through another spelling, `require.resolve`, caller-relative missing files, builtin spellings, a dual package, default exports through static imports, `require()` of pending and settled async factories, static imports of a slow and a rejected async factory, an async factory that imports another module, two async factories importing each other's targets, a factory started by `require()` that imports after awaiting, concurrent imports of a slow factory and the argument errors with native Bun on every engine.
