`Bun.color(input, format)` parses CSS colors with Bun's own `bun_css` parser and formats them exactly as `color_js.rs` does: `css`, `hex`/`HEX`, `rgb`/`rgba`, `hsl`, `lab`, `number`, the array and object forms, and the ANSI escapes (`ansi-16`, `ansi-256`, `ansi-16m`, and `ansi`, which follows Bun's terminal color depth from `bun_core`). The JavaScript side reads inputs into RGBA the way `js_function_color` does. A number goes through `to_int64` (saturating, NaN is 0) and keeps its low 32 bits, with alpha only above 24 bits. An array-like (an array that is not a proxy, a typed array, or an ArrayBuffer, whose length is its byte length) must have 3 or 4 elements; its length is read once through the intrinsic getters, so an own `length` or a getter that grows the array changes nothing, and its elements are read from the object itself, so an ArrayBuffer's own index properties count; any other object, a function included, is read as `{ r, g, b, a }`. Each channel must be a number, cast to i32 with saturation and clamped to 0 to 255; alpha is any number, 0 and NaN included, times 255, and anything else is opaque. A symbol throws `Cannot convert a symbol to a string`, and any other value is parsed as CSS text. The browser engine cannot detect a proxy from JavaScript, so there a proxy around an array is read as the array. The JSValue builders become a small result enum crossing the `Transpiler` trait. Text that is not a color returns `null`, as in Bun. `Bun.color` can be reassigned, as Bun's own writable property can.

`tests/fixtures/bun-probe-utils` compares eleven inputs and formats with native Bun on every engine.
